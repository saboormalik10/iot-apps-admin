# Work log — 7 September 2026

One day's work: a production data-delivery bug, the alerting surface, and time
filters across the panel.

**Headline:** a quarter of the station's files were arriving **10 hours late**,
so alarms were firing up to 10 hours after the wind. Found, fixed, deployed.

---

## 1. Data was arriving 10 hours late — fixed in production

`ingest-agent/src/watcher.ts`

Measured on the live station: of 756 files, **200 arrived 605 minutes late** —
every one of them, to within 6 seconds. That number is the bug's signature:
**600** (Sydney's UTC offset) **+ 5** (the agent's grace period).

Two defects, compounding:

| # | Defect | Effect |
| --- | --- | --- |
| 1 | The "is this file complete?" gate required the last row to end at second `:59`. The logger routinely closes a file with the **next** minute's `:00` row — which is *more* than complete | **193 of 199** late files took the slow path for being too complete |
| 2 | `minuteFromName` built a UTC timestamp from a filename written in the **station's local time**. For a +10 station that put every file 10 hours in the future, so the 5-minute grace period could not elapse | Turned a 5-minute wait into 605 |

Either alone was mild. Together they delayed ~26% of all files.

**Fixed:** completeness is now judged from the rows' own timestamps (no timezone
knowledge needed), and the grace period measures from file `mtime` — the same
clock the first gate already trusts.

**Deployed** to the Lightsail box; all three ingest agents restarted. 132 stuck
files drained in ~2 minutes, 0 rejected. Every hour is now **60/60 files**, and
the newest reading sits under a minute behind live.

A rollback copy is at `/opt/observator/ingest-agent/dist.bak-20260907-125930`.

> Also fixed a mirror bug nobody had hit yet: for a station **west** of UTC the
> same code released files **too early**, accepting genuinely truncated data.

## 2. Alerts

### The unit field was decorative

`admin-web/features/alerts/` · `backend/src/alert-rules/`

- Unit was a free-text box; it is now a **dropdown that changes with the sensor**
  (wind → km/h · m/s · knots · mph; temperature → °C · °F, and so on)
- The real defect underneath: the threshold was compared **without converting**.
  A rule written as "wind > 20 km/h" was tested as 20 m/s, so it could only fire
  at 72 km/h — above anything this station has ever recorded. It looked armed and
  could not fire
- Notification text now reports the reading in the rule's unit
  (`read 35.89km/h`, previously `read 9.97km/h` for the same value)
- Same mismatch fixed in the alert log, converted server-side so there is only
  one implementation of the conversion

### Alerts now record when the wind blew

Triggers stored only the moment the server processed a file. During the delivery
backlog above, that was hours after the reading. Triggers now carry
`measuredAtMs`, so an alert can be plotted against the readings that caused it.

### New: "why didn't my alert fire?"

- **Alert notifications open in place** with reading vs threshold, and a chart
  **centred** on the alert — a gust that spiked and dropped looks identical to a
  rising storm if you only see the run-up
- **Alerts → rule → "What this rule saw"**: minute-by-minute, with a
  1 min / 5 / 15 / 30 / 1 hour selector
- Every minute carries a verdict: **Fired · Held (cooldown) · Below threshold ·
  No readings · Rule paused**. The two that actually happen — never crossed, and
  swallowed by a cooldown — are indistinguishable from outside the system, which
  is the whole reason the panel exists
- The newest minutes show an animated **"Waiting for data"** rather than claiming
  "No readings" for a file that simply has not arrived yet

## 3. Time filters, across the panel

Every filter already meant "now − N". The bug was that several pages **displayed
numbers describing something else**.

| Page | Before | After |
| --- | --- | --- |
| Records `?range=1h` | **returned nothing** | returns the record |
| Records — Duration | `153 min` (the whole day) | **`60 min`** · *of 188 min that day* |
| Records — Measures | `9,176` (the whole day) | **`3,598`** · *of 11,275 that day* |
| Dashboard KPIs | all-time, ignored the range | **follow the range**; Devices/Online stay "now" |
| Stations | a range control that did nothing | removed (type + device still filter) |
| 7 other pages | scope bar shown but unread | hidden |

- The Records filter asked whether a day **started** inside the window. A record
  spans a whole local day, so any range shorter than a day matched nothing. It
  now matches on **overlap**
- Added **Today / Yesterday / Last 7 days**, computed against the **viewer's**
  local midnight — someone in Karachi and someone in Sydney each get their own
  day. Proven in real subprocesses under three timezones
- Record detail now reads **"Station day 2026-09-08 · Australia/Melbourne"**, so a
  station date beside a local start time stops looking like a bug

## 4. Settings and pages

- **Timezone is now a dropdown of all 421 IANA zones**, grouped by region, each
  showing its live offset, with your own zone offered first. It was free text —
  and a typo does not fail loudly: ingest falls back to `UTC`, so a customer's
  days would be cut on the wrong boundary and only look wrong much later. The API
  now rejects invalid zones and normalises the spelling of valid ones
- **Import data** switched off at the feature flag — nav hidden, route 404s,
  command palette excludes it. Files untouched and still type-checked, so it
  compiles the day it is wanted back. **Exports are unaffected**
- **Users** now lists everyone who can sign in (admins, operators, viewers). The
  MET and NEP tabs listed *mobile-app* users; the apps were switched off in M15
  and no user in the organisation carries a `mobileAppType`, so both were
  permanently empty
- **Notifications**: removed the "Registered devices" push-token section — all 37
  rows were CI artifacts for an app that has been disabled since M15
- **Share links**: deleted all 33, every one a test leftover

## Verification

~50 new tests. **347 frontend**, **79 backend** (the records / dashboard / alert /
timezone suites), **42 agent** — all green, both typechecks clean.

> The full backend suite still carries the **26 pre-existing failures** recorded
> in the M24 delivery report, from the M15 mobile/NEP shutdown and the M13 demo
> purge. None are from today's work, and none were fixed by it.

Every fix was reproduced before it was written, and each new test was checked to
**fail** when its fix is reverted. Two cases are worth knowing about:

- The DST test initially passed against the *buggy* implementation, so it proved
  nothing. Testing at 00:30 on the day after a spring-forward exposed the real
  failure: naive `now − 86,400,000` arithmetic **skips a whole day**, so
  "Yesterday" would silently show the wrong date for one hour, once a year
- The timezone list is built from `Intl.supportedValuesOf`, which **omits `UTC`
  entirely**. Since `UTC` is the platform default, an organisation set to it
  would have seen a blank field with no way to re-select it
