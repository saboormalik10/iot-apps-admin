-- THE PROBLEM ---------------------------------------------------------------

The station detail page (/devices/<id>) rendered a full grid of tiles that were
permanently empty for a MET-LINK / SFTP-ingested station. Live example, the
"WindSonic — Sydney" MET-LINK wxstation:

    Sessions            0
    Last activity       –
    Firmware            –
    Battery             – (no reading)
    Battery voltage     – V
    Firmware age        –
    Firmware history    "No firmware history"
    Last seen           2 minutes ago     <-- real
    Sync lag            59s               <-- real

Not a bug in the tiles. Those fields have no writer on the ingestion path.


-- ROOT CAUSE: WHO WRITES WHAT ------------------------------------------------

Written by SFTP/CSV ingestion — backend/src/ingest/ingest.service.ts, in
afterBatch() around line 421:
    Device.lastSeenAt
    Device.isOnline
    Device.availableSensors / sensorsUpdatedAt
    Device.reportedSpeedUnit
=> Last seen, Sync lag and the Online badge are genuinely live. KEEP.

Written ONLY by the mobile BLE heartbeat — PATCH /sync/device-status,
backend/src/sync/sync.service.ts updateDeviceStatus() lines ~85-105:
    Device.lastBatteryPct        -> Battery meter
    Device.lastBatteryVoltage    -> Battery voltage row
    Device.lastBatteryCharging
    Device.firmwareVersion       -> Firmware tile
    FirmwareHistory rows         -> Firmware history card AND firmwareAgeDays
=> Null forever on an ingest-fed station. Nothing else in the codebase writes
   them (verified by grep across all of backend/src).

Written ONLY by NEP-LINK mobile session upload — NepSession collection:
    getDeviceStats() counts NepSession docs
=> Sessions and Last activity. A MET-LINK station has no sessions by
   construction, so these are 0 / "–" by design, not by fault.

alertCount24h was a hardcoded 0 in getDeviceHealth ("populated once alert
evaluation ships (Month 6)"). Alert evaluation shipped elsewhere; this never
got wired.


-- THE ONE EXCEPTION: BATTERY VOLTAGE IS AVAILABLE ----------------------------

Battery voltage is NOT actually missing — it is ingested, it was just being
read from the wrong place. The CSV carries it and it lands on:

    MetMeasure.batteryVoltageV

which the dashboard live tile already reads (dashboard.service.ts getMetLatest,
~line 357). The detail page was reading Device.lastBatteryVoltage (BLE only)
instead. So battery voltage was REWIRED, not removed.


-- DECISIONS TAKEN (confirmed with Saboor) ------------------------------------

1. Remove the dead widgets OUTRIGHT (not conditionally hidden per device type,
   not hidden-when-null). Simpler page, one code path.
2. REWIRE battery voltage to the ingested MetMeasure.batteryVoltageV rather
   than dropping it.

Consequence to be aware of: the removal is unconditional, so NEP-LINK / BLE
devices also lose these tiles from the detail page even though their heartbeat
does populate them. That was the explicit choice. If NEP-LINK detail ever needs
them back, reintroduce them behind `device.type === 'NEP-LINK'`.


-- FILES CHANGED (5) ----------------------------------------------------------

1. admin-web/features/devices/device-detail.tsx           [rewritten]
   Removed: Sessions tile, Last activity tile, Firmware tile, Battery meter
            Card, the whole Firmware history Card, the Firmware age health row.
   Removed imports now unused: StatTile, Meter, History icon, EmptyState,
            formatDateTime, useDeviceStats, useFirmwareHistory.
   Kept: header (icon, name, type, bleId, Online/Offline badge), the
            Settings/Edit/Delete actions, EditDeviceDialog, ConfirmDialog.
   Health Card is now 3 columns: Last seen | Sync lag | Battery voltage,
            and Battery voltage renders only when non-null.
   A block comment at the top of the component records WHY each widget went,
            so nobody re-adds them.

2. admin-web/features/devices/use-devices.ts
   Deleted hooks useDeviceStats() and useFirmwareHistory() — device-detail.tsx
   was their only consumer (verified by grep across features/ lib/ test/ e2e/).
   Deleted the matching getDeviceStats / getFirmwareHistory imports.
   useDeviceHealth() kept.

3. admin-web/lib/api/types.ts
   DeviceHealth interface trimmed to: deviceId, isOnline, lastSeenAt,
   batteryVoltage, lastSyncAt, lastSyncLagSeconds.
   Dropped: batteryPct, batteryCharging, firmwareVersion, firmwareAgeDays,
   alertCount24h. Doc comment added explaining why.

4. backend/src/devices/devices.service.ts
   getDeviceHealth() now returns only the six fields above. The FirmwareHistory
   lookup it used for firmwareAgeDays is gone.
   NEW private helper latestBatteryVoltage(device):
       - MET-LINK  -> newest MetRecord for the device (sort dateStartMs desc)
                      -> newest MetMeasure on that record with
                         rowType:'data' AND batteryVoltageV: {$ne: null}
                      -> falls back to device.lastBatteryVoltage
       - otherwise -> device.lastBatteryVoltage (BLE heartbeat)
   The $ne:null filter is deliberate: batteryVoltageV is an optional column, so
   the single newest row often has none while a row minutes earlier does.
   Both queries ride existing indexes: {deviceId, dateStartMs} on MetRecord and
   {recordId, rowType, timestampMs} on MetMeasure.
   New imports: MetRecord, MetMeasure.

5. admin-web/e2e/dashboard-devices.spec.ts
   The device-detail assertion looked for the 'Firmware history' heading. Now
   asserts the health summary (Last seen / Sync lag) instead.
